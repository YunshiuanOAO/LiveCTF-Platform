# NCKUCTF 現場資安競賽系統

現行版本支援 2～30 個偶數組別，每組 1 或 2 人。系統沒有座位表、隊伍登入碼或電腦編號選擇；每組只使用一台隊伍介面，並在每輪由 Host 開放後輸入全組學號。

## 啟動

需要 Node.js 24 以上。

```bash
cd /home/yunshiuan/arena-ctf
npm ci
npm run setup
npm run seed
npm start
```

現場網址預設為 `http://10.77.1.1:3000`，實際以 `.env` 的 `PUBLIC_URL` 為準。

若同時透過 Cloudflare Tunnel 與教室內網操作，將兩種來源列在 `.env` 的 `ALLOWED_ORIGINS`，以逗號分隔。正式 Tunnel 網址目前為 `https://livectf.yunshiuan.com`。

| 入口 | 用途 |
| --- | --- |
| `/` | 即時戰況與排名 |
| `/admin` | Host 管理報到、配對、題目與開賽 |
| `/register` | 學員輸入隊名及 1～2 位學號，系統自動分配組別位置 |
| `/play` | 單一隊伍介面：顯示移動場地、學號登入、題目與 flag 輸入 |

完整現場流程、電腦配置與計時規則見 [OPERATIONS-V2.md](OPERATIONS-V2.md)。

## 核心規則

- 報到時輸入隊伍名稱與全組 1–2 位學號。
- Host 鎖定報到後不能再新增隊伍，系統立即隨機配對。
- Host 可設定總輪數；最後一輪結束後不再產生新配對。
- Host 可在沒有進行中對局時解鎖報到；尚未開始的配對會取消，之後重新鎖定並重新配對。
- Host 可在報到開放且隊伍尚無對局紀錄時，修改隊名、1～2 人的組員學號，或刪除組別。
- 總組數必須是偶數。若為奇數，最後報到的雙人組自動拆成兩個單人組；最後一組不是雙人組時拒絕鎖定。
- 每個場地正好兩組，場地內編號固定為 1、2；每組使用一台 `/play` 隊伍介面，進入後直接依賽事階段顯示內容。
- 鎖定報到後，隊伍介面先顯示該組應前往的場地與對手。Host 按「開始對局準備」後，畫面才切換為學號登入。
- 每輪開始前，各組都必須重新輸入全組學號；若有人發生問題，Host 可確認缺席名單後強制開始。
- 強制開始後，遲到隊伍仍能使用該輪剩餘時間補登入作答，整輪計時不會重新開始。
- 對局準備期間，Host 的「對局與隨機配對」會列出尚未完成本輪學號登入的隊伍及其場地，並即時移除已完成的隊伍。
- 第一個正確 flag 決定勝負；另一組可在限時內補交並保存實際解題時間。
- 題目敘述支援 Markdown，可在 Host 題目庫上傳 PNG、JPEG、GIF 或 WebP 圖片並即時預覽；單張上限 5 MB。
- Host 可新增、修改、刪除及重新使用題目。重新使用會把原題恢復為可選狀態，不會在題目庫增加副本；既有局次仍保留當時版本。準備中或進行中的題目不可修改、刪除或重新使用。
- Host 可先安排練習題；練習結束後按「清除練習成績」，即可保留隊伍、學號、題庫及裝置識別，清除所有配對、作答與成績。報到已鎖定時會立即重新隨機配對，再選正式題目即可開始。
- Host 可在服務持續運行時重設競賽，清除隊伍、局次、配對、成績與隊伍登入，並保留題目庫及圖片供下一梯次使用。
- 未完成者將該題完整限時計入累計時間。
- 每輪結束立即撤銷所有隊伍的送旗權限，隊伍介面自動顯示下一輪移動位置；完成設定輪數後則顯示最終成績。
- 下一局重新隨機配對，並優先避開上一局對手。

## 資料與備份

資料位於 `data/arena.sqlite`。升級前的資料庫與原始碼已存入 `data/backups/`。新版本首次啟動會將舊資料表遷移到 1–2 人隊伍格式，移除舊座位表、登入碼與 QR 卡片流程。

```bash
npm run backup
```

此命令會以 SQLite 一致性快照建立備份，不需停止服務。
